SECTION 1: PROJECT OVERVIEW

What is ResumeIQ?

ResumeIQ is an AI-powered SaaS (Software as a Service) platform that helps job seekers audit, optimize, and edit their resumes. It simulates the screening systems used by companies and provides feedback to increase job search success.

The Core Problem

When a candidate applies for a job online, their resume is processed by an ATS (Applicant Tracking System)—a software filter that scans resumes for specific keywords and formatting styles.

The Issue

If a resume has unparseable layouts (like two columns, tables, or icons) or lacks the exact technical terms mentioned in the job description, it is immediately discarded.

Up to 75% of resumes are filtered out automatically before a human recruiter ever sees them.

The Solution

ResumeIQ simulates ATS filters by:

  • Extracting text from PDF resumes.
  • Running ATS compatibility tests.
  • Using AI to suggest and insert missing keywords.
  • Simulating mock interviews to help candidates prepare.

💡 Beginner Concept: What is a Web App?

A web app (web application) is an interactive website that processes files, calculates scores, communicates with external databases, and saves account settings (like Gmail, Spotify, or Notion).

How ResumeIQ Uses It: ResumeIQ is a web app because it processes file uploads, communicates with AI, and stores account details in a database.

💡 Analogy: The Strict Club Bouncer

Imagine trying to get into an exclusive VIP club. The club has a strict bouncer checking:

  • Dress Code – Are your fonts and section headers formatted correctly?
  • Password – Do you have the required keywords (like SQL or Figma)?
  • Invitation Details – Does your target company or role match?

If you fail any check, you are rejected immediately. ResumeIQ is like your personal stylist standing next to you in line—helping you fix your clothes (formatting) and whispering the password (keywords) before you step up to the bouncer (the ATS).

SECTION 2: FEATURES & WORKFLOWS

1. PDF Resume Upload & Text Extraction

What It Does

Reads your uploaded PDF file and converts all the text inside it into a single JavaScript text string.

Why It Is Useful

Computers cannot read a PDF visually like we do; they need plain text. We must extract this text before we can run any checks.

Internal Workflow

When the file is uploaded, the backend uses a library called pdf-parse. This library:

  • Scans the binary pages of the PDF.
  • Extracts all letters and text.
  • Returns them as one clean text string.

2. Dynamic Career-Track Keyword Matching

What It Does

Checks your resume text for technical skills tailored to your target industry, including:

  • Software Engineering
  • Data Analytics
  • UI/UX Design
  • Product Management
  • Teaching
  • HR
  • Finance/CA

Why It Is Useful

It ensures that a teacher is graded on education skills (like Lesson Planning) while a developer is graded on technical skills (like React).

Internal Workflow

The server checks the target role, selects the corresponding keyword checklist, and uses case-insensitive Regular Expressions (RegExp) to find matching skills.

3. Real-Time Resume Builder Canvas

What It Does

Provides a split-screen interface where the left panel is an accordion input form, and the right panel is an A4 resume preview that updates instantly as you type.

Why It Is Useful

It allows users to visually edit and format their resumes without leaving the application.

Internal Workflow

As the user types, JavaScript captures keystrokes using DOM Event Listeners. The updated values are immediately inserted into the resume preview's HTML, and the preview refreshes in real time.

4. One-Click AI Resume Optimizer

What It Does

Automatically rewrites the resume's professional summary and experience section by adding missing ATS keywords.

Why It Is Useful

It saves users from manually figuring out how to naturally include important technical keywords.

Internal Workflow

The client sends the resume text and missing keyword list. The backend sends this data to Google Gemini. Gemini returns a cleaned JSON object containing rewritten summaries. The frontend automatically updates the input fields and redraws the resume preview.

5. Conversational Mock Interview Simulator

What It Does

Generates 5 customized interview questions (HR, Technical, Behavioral, and Project-based) based on the candidate's resume and target role.

Why It Is Useful

It helps candidates improve communication skills, technical interview performance, and confidence.

Internal Workflow

Gemini generates interview questions using the candidate's parsed profile. The user submits answers, and the AI grades each answer out of 100, highlighting strengths, weaknesses, and suggestions for improvement. Interview sessions are stored in MongoDB.

6. Social Portfolio Auditor

What It Does

Reviews links such as GitHub, LinkedIn, and Portfolio, and rates their branding and layout.

Why It Is Useful

Recruiters often review online profiles before hiring. An optimized profile increases credibility.

Internal Workflow

The frontend sends profile links to the backend. The backend evaluates their layout, Gemini (or fallback templates) generates recommendations, and results are returned to the frontend.

7. A4 PDF Print Exporter

What It Does

Exports the styled resume canvas as a clean, single-page A4 PDF.

Why It Is Useful

Ensures the resume maintains proper formatting after conversion to PDF.

Internal Workflow

The application uses a CSS @media print style block. When window.print() is called, the dashboard sidebar, forms, and headers are hidden, leaving only the resume canvas visible for printing.

SECTION 3: COMPLETE PROJECT FLOW

This is what happens from the moment a user opens the website until they receive the final output:

Step 1: Opens the Website

The browser loads index.html on http://localhost:3001. The Single Page Application (SPA) routing engine checks localStorage for a JWT token. If a valid token is found, the user stays logged in; if no token exists, the landing page is displayed.

Step 2: Registration / Login

The user creates an account or logs in.

  • Backend Process: Receives details, hashes the password using BcryptJS, stores the user in MongoDB, generates a JWT token, and returns it.
  • Frontend Process: Saves the JWT token inside localStorage to authenticate future requests.
Step 3: Upload Resume

The user opens the Upload tab, enters the target role (e.g., Data Analyst), target company (e.g., Netflix), and uploads a PDF resume.

Step 4: File Extraction

Once uploaded, Multer intercepts the file, and pdf-parse extracts all text. The text is sent to Google Gemini (or the offline fallback engine), which returns an ATS Scorecard JSON. The backend saves a new Resume version and the Analysis Report.

Step 5: Scorecard Visuals

The frontend router updates the URL hash to #analysis and generates a Chart.js Radar Chart showing scores for Formatting, Keywords, Skills, and Readability.

Step 6: Optimize with AI

The user navigates to the Resume Builder. Clicking "Run One-Click AI Optimizer" sends the resume text to Gemini, which rewrites the Professional Summary to naturally add missing ATS keywords. The canvas and inputs update instantly.

Step 7: Mock Interview

The user opens the Mock Interview tab. The application generates questions, accepts user answers, sends them to Gemini, and receives a score, feedback, strengths, weaknesses, and suggestions. The complete session is stored in MongoDB.

Step 8: Export PDF

The user clicks "Download PDF." The browser opens the Print Preview. The print CSS automatically hides the dashboard navigation and forms, leaving only the resume document visible for A4 PDF export.

The user interacts with the Frontend. The frontend sends API requests to the Express Backend. The backend verifies authentication, processes business logic, calls MongoDB when data needs to be stored or retrieved, and calls Google Gemini whenever AI analysis is required. The backend sends the final result back to the frontend, which updates the UI dynamically.

SECTION 5: TECH STACK DECONSTRUCTION

A Tech Stack is the collection of technologies, programming languages, frameworks, libraries, databases, and tools used to build an application.

  1. Node.js: A JavaScript runtime that allows JavaScript code to run on the server. We used it to build the backend server, process requests, handle uploads, and connect to APIs.
  2. Express.js: A lightweight web framework built on top of Node.js. It helps us create REST APIs, handle routing, process requests, and manage middleware.
  3. MongoDB: A NoSQL document database. It stores data as JSON-like documents. This is perfect for resumes because everything (skills, education, experience, projects) can be stored inside one document rather than many SQL tables.
  4. Mongoose: An ODM (Object Document Mapper) for MongoDB. It converts JavaScript objects into MongoDB documents, helping us create schemas, validate data, and run queries.
  5. Google Gemini API: Google's Large Language Model (LLM). We used it to perform semantic evaluations like resume analysis, keyword suggestions, resume optimization, and mock interview grading.
  6. Vanilla JavaScript: Plain JavaScript without using frameworks. We used it to build the Single Page Application, update the DOM, handle routing, manage events, and render the Resume Builder.
  7. Multer: Express middleware used for uploading files. It accepts uploaded PDF resumes, validates file types, and saves files temporarily.
  8. pdf-parse: A Node.js library used to extract text from PDF files. It reads binary PDF data and extracts all text, returning plain text for ATS analysis.
  9. BcryptJS: A password hashing library. Instead of storing passwords directly, it converts them into secure hashes so user accounts remain protected.
  10. JWT (JSON Web Token): A secure authentication token. After login, the server generates a signed token containing the user's ID. The browser stores it in localStorage and sends it with every authenticated request.

SECTION 6: FOLDER STRUCTURE BLUEPRINT

We organize our code into folders to keep the codebase clean and maintainable. ResumeIQ separates files according to their responsibilities:

  • config/: Stores configuration files (like db.js) that connect Node.js to MongoDB using Mongoose.
  • models/: Contains all Mongoose database schemas (User, Resume, AnalysisReport, MockInterview) defining how data is stored inside MongoDB.
  • middleware/: Contains functions that run before controllers (like `authMiddleware.js` to verify JWT tokens and block unauthorized users).
  • controllers/: Contains the application's business logic (like `resumeController.js`). Controllers receive requests, process data, call services, query MongoDB, and return responses.
  • routes/: Defines API endpoints. It maps URLs (like login, register, upload resume, optimize resume, interview) to their respective controllers.
  • services/: Houses third-party integrations (like `pdfService.js` and `geminiService.js` to parse files and manage AI prompts).
  • public/: Contains frontend files (HTML, CSS, JavaScript) that run in the user's browser.

SECTION 7: FRONTEND ARCHITECTURE & SINGLE PAGE ROUTING

1. Hash-Based SPA Routing

SPA stands for Single Page Application. Instead of loading a new HTML page every time a user clicks a menu option, the application loads one HTML file (index.html) and dynamically changes the visible content using JavaScript. All sections exist inside the same index.html file. When the user clicks a navigation option, the URL hash changes (e.g. from /#dashboard to /#builder). JavaScript listens for this hash change and decides which section should be displayed:

window.addEventListener('hashchange', routeHandler);

2. Client-Side State Management

State means the current data of the application that JavaScript remembers while the application is running. The frontend stores important data inside a single JavaScript object:

const state = {
    user: null,          // Logged-in user information
    resumes: [],         // All uploaded resume versions
    currentResume: null, // Resume currently being edited
    currentReport: null  // ATS report currently displayed
};

3. DOM Manipulation (Updating the Screen)

DOM stands for Document Object Model. DOM Manipulation means changing the webpage dynamically using JavaScript. For example:

document.getElementById("sidebar-user-name").innerText = state.user.name;

JavaScript finds the element whose ID is sidebar-user-name, reads the logged-in user's name from the state object, and updates the sidebar instantly.

💡 Beginner Concept: What is DOM Manipulation?

Think of the webpage like a notebook. HTML creates the notebook. The DOM is the notebook opened in memory. JavaScript acts like a pen. Whenever JavaScript writes something new, erases text, changes colors, or inserts new elements, it is performing DOM Manipulation.

SECTION 8: BACKEND & DATABASE SCHEMAS

1. Request Lifecycle

Whenever the frontend sends a request to the backend, it passes through several stages:

  1. Route: Receives the incoming request (e.g. POST /api/resumes/upload) and forwards it to the correct controller.
  2. Middleware: Performs checks before the request reaches the controller (e.g., verifies JWT Token). If verification fails, the request stops here.
  3. Controller: Contains the business logic. It decides what should happen, which database query should run, and whether Gemini should be called.
  4. Service: Handles external operations (like parsing PDF files or calling Gemini).
  5. Response: The controller sends the final response back to the frontend, which updates the UI.

2. Database Schemas (Mongoose)

A. User Schema (models/User.js)

Stores user account information. Fields include:

  • name: Stores the user's full name.
  • email: Unique login identifier.
  • password: Stores the encrypted password using BcryptJS instead of plain text.

B. Resume Schema (models/Resume.js)

Stores uploaded resumes and their different versions. Fields include:

  • user: Reference link to the User collection.
  • parentResumeId: Links different versions of the same resume together (V1 -> V2 -> V3) to track changes over time.
  • version: Stores version numbers (1, 2, 3).
  • parsedText: Stores the text extracted from the uploaded PDF.

SECTION 9: AUTHENTICATION FLOW

Authentication verifies a user's identity before allowing access to protected resources.

1. Password Hashing (BcryptJS)

Passwords should never be stored in plain text. When a user registers:

  • User enters a password.
  • Backend generates a random Salt.
  • Bcrypt combines the password and salt to generate a secure hash, which is stored in MongoDB.
  • During login, bcrypt.compare() hashes the entered password again and checks if it matches the stored hash.

2. Stateless JWT Authorization

JWT stands for JSON Web Token. After successful login, the server creates a JWT signed with a secret key. The browser stores it in localStorage. For every protected API request, the browser sends the token in the header:

Authorization: Bearer <token>

The backend reads the token, verifies its signature, extracts the user ID, and grants access if valid. This makes the application fast and scalable because the server does not store login sessions.

💡 Beginner Concept: What is a JSON Web Token (JWT)?

Imagine checking into a hotel. Instead of asking the receptionist every time you enter your room, you are given a key card (the JWT). The key card already contains your room information. Whenever you tap it, the door scanner verifies the card and opens without calling the front desk.

SECTION 10: FILE UPLOAD & ATS SCORING ENGINE

1. File Upload & Parsing

  • Multer Receives the File: Multer accepts PDF uploads, validates that the MIME type is application/pdf, and saves the file temporarily inside the /uploads/ folder.
  • PDF Parsing: The backend passes the file to pdf-parse, which reads binary data, extracts text, and returns one clean text string.
  • File Cleanup: Once text extraction is complete, the server immediately deletes the uploaded PDF using fs.unlink() to protect user privacy and save space.

2. Heuristic Scoring Calculations

Before calling Gemini, ResumeIQ performs several local ATS checks using predefined rules (heuristics):

  • Structure Score: Checks whether important sections (Experience, Education, Skills, Projects) exist using Regular Expressions (Regex).
  • Readability Score: Evaluates the total number of words. The optimal range is 300–800 words; resumes that are too short or too long receive lower scores.
  • Formatting Score: Counts formatting elements like bullet points (•, -, *) to verify consistency.

💡 Beginner Concept: What is Regex?

Regex (Regular Expression) is a search pattern used to find specific text inside larger blocks of text (like email addresses, phone numbers, or section headings).

SECTION 11: THE AI ENGINE & PROMPT ENGINEERING

The AI Engine is the intelligent part of ResumeIQ. It uses Google Gemini 1.5 Flash to perform semantic analysis (understanding context and meaning rather than simply searching for exact keywords).

1. Prompt Engineering

Prompt Engineering is the process of writing clear instructions for an AI model so that it returns a clean JSON object containing the exact structure we need:

const prompt = `
  You are a professional recruiting coordinator.
  Analyze the following resume text. Your evaluation must be tailored specifically to the target role of "${targetRole}" and target company "${targetCompany}".
  
  Resume Content:
  "${resumeText}"

  Return a JSON object matching this schema:
  {
    "overallScore": number (0-100),
    "scores": { "skills": number, "keyword": number, "formatting": number },
    "skillsMatch": {
      "matched": ["string"],
      "missing": ["string"]
    }
  }
`;

2. Offline Fallback Engine (No API Key Mode)

If GEMINI_API_KEY is not available, the backend automatically switches to the fallback engine. It uses local Regex searches and target-role keyword lists (supporting Developer, Designer, PM, HR, Teacher, CA, MBA) to calculate scores and generate structured analysis reports offline.

2. Technical Challenges & Solutions

Challenge A: RegExp Compilation Crash

Problem: The local fallback engine scans the resume text for technical skills using regex patterns. If a candidate targeted a role like "C++ Developer," compiling the regex pattern (new RegExp('\\bC++\\b')) threw a syntax crash because + is a special quantifier in regular expressions.

Solution: I added an escapeRegex utility function that escapes regex-specific characters (turning C++ into C\+\+) to compile the search pattern safely.

Challenge B: Hoisting & UI Boot Crashes

Problem: In JavaScript, variables declared with const are not hoisted. In my initial code, calling a rendering helper before declaring it with const crashed the script on boot, which also blocked the dropdowns and tab navigation from working.

Solution: I changed the const function expressions to standard function declarations, which are hoisted by the browser engine on startup.

Challenge C: Blank PDF Export Previews

Problem: Hiding the dashboard controls during print was hiding the main parent wrapper (#app-wrapper). Since the resume canvas is inside this wrapper, the print preview rendered as a blank white page.

Solution: I removed #app-wrapper from the hidden print styles list in styles.css. This kept the main container visible, while still hiding the sidebars, forms, and headers.

SECTION 16: INTERVIEW Q&A PREPARATION

20 Common Interview Questions & Answers

  1. What is the difference between a Local Score and an AI Score?
    Answer: The Local Score uses heuristic algorithms running on the server to evaluate resume structure, formatting, section headings, and word count. The AI Score is generated by Google Gemini, which performs semantic analysis to determine how well the resume matches the target role.
  2. How did you resolve the RegExp crash on terms like "C++"?
    Answer: Characters like + have special meanings in Regular Expressions. Creating a Regex directly using C++ caused a syntax error. I solved this by creating an escapeRegex() utility function that converts C++ into C\+\+, allowing Regex to compile safely.
  3. What is the role of Multer in the resume upload flow?
    Answer: Multer is Express middleware that handles multipart file uploads. It receives uploaded PDFs, validates file types, saves files temporarily, and makes them available to backend controllers.
  4. What is Hoisting, and how did it cause a bug?
    Answer: Hoisting is JavaScript's behavior of moving declarations before execution. Functions declared with const are not hoisted. Calling a rendering helper before its declaration threw a ReferenceError, preventing the UI from loading. I fixed it by converting helper functions into standard function declarations, which are hoisted.
  5. Why is MongoDB called a NoSQL Database?
    Answer: MongoDB stores information as flexible JSON-like documents instead of rows and columns. This makes it ideal for resumes because resumes contain nested data (skills, experience, projects) without requiring multiple SQL joins.
  6. How does your application protect passwords?
    Answer: Passwords are hashed using BcryptJS before being stored. Bcrypt combines the password with a random salt and performs one-way hashing; original passwords cannot be recovered.
  7. What is JWT, and how does your application use it?
    Answer: JWT (JSON Web Token) is a signed authentication token. After login, the server generates a JWT, the browser stores it in localStorage, and every protected request sends the token in the Authorization header. The server verifies the token before granting access.
  8. What is CORS, and why did you configure it?
    Answer: CORS (Cross-Origin Resource Sharing) is a browser security feature that controls communication between different domains. I configured CORS middleware to allow secure communication between the frontend and backend APIs.
  9. Why did the print preview initially show a blank page?
    Answer: The print stylesheet hid #app-wrapper. Since the resume canvas was inside this container, the entire resume disappeared during printing. Removing it from the hidden print elements solved the issue.
  10. How does your application parse PDF files?
    Answer: The application uses pdf-parse to extract plain text from binary PDF files, which is then used for ATS analysis and AI processing.
  11. What is a Single Page Application (SPA), and why did you build the frontend this way?
    Answer: A Single Page Application loads one HTML page and dynamically updates its content using JavaScript without reloading the browser. This provides faster navigation, better user experience, and lower server load.
  12. How does the Mock Interview module grade answers?
    Answer: The backend sends the interview question, category, and user's answer to Google Gemini. Gemini evaluates the response and returns a score (out of 100), strengths, weaknesses, and suggestions for improvement.
  13. What happens to uploaded PDF files after parsing?
    Answer: After extracting text, the server immediately deletes the uploaded file using fs.unlink() to protect user privacy and save storage space.
  14. What are Mongoose References?
    Answer: Mongoose references create relationships between collections. For example, the Resume schema stores the ObjectId of the User schema, allowing resumes to be linked to specific users.
  15. How does the system handle backend errors?
    Answer: The application uses centralized error-handling middleware. Controllers pass errors using next(error), which catches the error and sends a clean, standardized response to the frontend.
  16. What is the difference between Authentication and Authorization?
    Answer: Authentication verifies who the user is. Authorization determines what the user is allowed to access.
  17. How does the Resume Builder update in real time?
    Answer: Input fields have JavaScript event listeners attached. Whenever the user types, JavaScript reads the updated values, updates the DOM, and redraws the resume preview canvas without reloading the page.
  18. Why did you choose MongoDB instead of SQL?
    Answer: Resume data is hierarchical and contains nested information. MongoDB stores nested JSON documents naturally, whereas SQL would require multiple related tables and joins.
  19. What is a .gitignore file, and why is it important?
    Answer: A .gitignore file tells Git which files should not be uploaded to the repository (like node_modules/ or .env containing API keys) to protect sensitive information.
  20. How would you scale this project for production?
    Answer: I would store uploaded files in AWS S3, use Redis for caching, integrate OCR (Tesseract.js) to support scanned image PDFs, and optimize database performance.
